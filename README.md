# Multi-Tenant Inventory Management SaaS — Starter

A beginner-friendly starter for the 7-task project brief.

## Stack
- Frontend: React + Vite + TypeScript
- Backend: Node.js + Express + TypeScript
- Database: PostgreSQL on Neon
- Database access: `pg` (SQL is explicit and easy to inspect)
- Authentication: JWT access token + bcrypt password hashing
- Authorization: role-based middleware
- Validation: Zod

## Important architecture note
This starter supports **master database + tenant databases**. Creating a PostgreSQL database is a privileged operation and direct `CREATE DATABASE` often is not available to a normal Neon application connection. This starter therefore uses the Neon API for tenant database provisioning. You must configure your Neon API key, project ID, and branch ID. Confirm the API permissions and database owner setup for your Neon project before using it beyond local development.

The starter names each tenant database from the organization's name, normalized to a lowercase PostgreSQL-safe slug (for example, `Acme Retail` becomes `acme_retail`). Names that normalize to the same database name cannot be registered separately. Tenant connection details are derived from environment configuration; database URLs are never accepted from the browser. If your Neon account/API configuration cannot create databases, use a documented shared-database tenant design instead; do not disable tenant checks.

Sign-in success and failure events are stored in the master database and included in the organization's activity log. Run `npm run db:migrate` after updating to create the master authentication-events table.

## Prerequisites
- Node.js 20+ (Node 22 LTS recommended)
- npm
- Neon account and a PostgreSQL database for the master database
- Neon API key, project ID, and branch ID if enabling automatic tenant DB provisioning

## Setup
1. Copy `.env.example` to `backend/.env`.
2. Fill in `MASTER_DATABASE_URL`, `JWT_SECRET`, and Neon provisioning settings.
3. Install dependencies:
   ```bash
   cd backend
   npm install
   npm run db:migrate
   npm run dev
   ```
4. In another terminal:
   ```bash
   cd frontend
   npm install
   npm run dev
   ```
5. Open the Vite URL printed in the terminal.

The master migration can also be run using:
```bash
cd backend
npm run db:migrate
```

## First use
- Sign up an organization. The first registered account becomes its Super Admin.
- Sign in using Organization ID, email, and password.
- Add products in Inventory.
- Public catalog URL: `http://localhost:5173/order/<organizationId>`
- Public API: `GET http://localhost:5000/api/public/products/<organizationId>`
- Customer order API: `POST http://localhost:5000/api/public/orders/<organizationId>`

## Starter limitations / required production work
- Neon API database provisioning is implemented as a best-effort adapter; verify API response fields and permissions against your Neon project before use.
- Initial employee invitations and full account-management UI are not included; this starter focuses on organization signup, auth, products, orders, subscription display, and activity logs.
- JWT access tokens are stored in browser memory for this starter. Production should use a carefully designed secure session or refresh-token rotation strategy.
- Password reset, email verification, MFA, billing integration, bot protection, and production deployment are not included.
- Public order creation reserves stock using a transaction and row lock.
- For production, add automated tests, centralized monitoring, backups, retention policies, and security review.
- Never commit `.env`; use managed secrets in deployment.

## Security notes
- Organization IDs in URLs are identifiers, not credentials.
- Tenant context is resolved from the authenticated user's master-database record.
- Tenant DB names are generated by the server.
- Activity logs do not store passwords or tokens.
- Every protected API route uses authentication and tenant-aware database resolution.
